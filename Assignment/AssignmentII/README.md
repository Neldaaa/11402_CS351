# Assignment II: SDD, BDD, and TDD in AI-Assisted Software Development

## 📝 About This Assignment
<div align="justify">
  
This assignment focuses on three critical software development methodologies in the AI era: **Specification-Driven Development (SDD)**, **Behavior-Driven Development (BDD)**, and **Test-Driven Development (TDD)**. 

The core task was to design the requirements, behaviors, and test cases for a **Student Grade Calculator** without writing the actual source code. The goal was to practice how to communicate software behavior clearly to guide AI-generated output efficiently[cite: 2].
</div>

## 🚀 How It Was Done
<div align="justify">
  
1. **Scenario Analysis:** Analyzed the specific weighting rules (Assignment: 30%, Midterm: 20%, Final: 30%, Project: 20%) and the exact grade interval thresholds (A, B, C, D, F).
2. **Applying SDD:** Defined clear functional requirements, expected inputs/outputs, and strict acceptance criteria[cite: 2]. I created original boundary and invalid input constraints.
3. **Applying BDD:** Wrote multiple user scenarios using the Gherkin syntax (`Given-When-Then`) covering normal cases (e.g., getting an A), edge cases, and invalid inputs to simulate real-world behavior.
4. **Applying TDD:** Designed structured test cases outlining the expected calculation logic and outputs before any code implementation, setting a baseline for verifying AI-generated code.
5. **Reflection:** Compared the three methods and reflected on how they act as essential "guardrails" when prompting AI coding tools.
</div>

### Brief Reflection Summary
Through this assignment, I learned that AI tools are fast but lack inherent context. **SDD** helps me define the strict rules, **BDD** helps me communicate user expectations in natural language, and **TDD** provides the objective verification mechanism to test if the AI succeeded. Moving forward, I will always establish these standards before generating code.
